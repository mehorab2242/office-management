# Phase 4 V1 Completion Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Complete the office cost application with reporting, exports, controlled workbook import, administration, attachments, dashboard polish, and production verification.

**Architecture:** Extend the existing versioned JSON API and shared Vue shell. Keep one reusable expense filter/query boundary for reports and exports. Use PhpSpreadsheet for workbook reading/writing and Dompdf for server-rendered PDFs. Store import previews in the existing import batch/row tables and commit selected valid rows in one database transaction.

**Tech Stack:** Laravel 13, PHP 8.4, MySQL/SQLite tests, PhpSpreadsheet, Dompdf, Vue 3, TypeScript, Pinia, Axios, Tailwind CSS 4, Reka UI, Vitest, PHPUnit.

**Verified source workbook:** `C:/Users/mehra/Downloads/Office Cost management List.xlsx`

## Constraints

- Preserve the Phase 1 schema and Phase 2/3 API conventions.
- Import ledger sheets only when the user selects and maps them; keep `Marketing cost` and `Item` separate from the main expense ledger.
- The original workbook has no category or payment status columns. Never invent those values.
- Use date, normalized description, amount, payer, source sheet, and source row as duplicate evidence rather than claiming natural uniqueness.
- Restrict imports, users, audit logs, and category administration to admins.
- Keep receipt files private and authorize every download/delete.
- Skip a database-backed settings page because V1 settings remain deployment configuration and the current architecture has no settings store.

## Review Focus

- Formula cells must import their cached numeric values and reject missing/invalid cached results.
- Re-uploading the same file or committing the same preview must not duplicate expenses.
- Filtered exports must use the same filters as the displayed report and expense list.
- Staff must never access admin reports, imports, user management, or audit data through direct API calls.
- Failed imports must roll back every expense and row status change.
